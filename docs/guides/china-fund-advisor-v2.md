# 中国公募基金助手 V2：概率预测与多 Agent 审查

V2 在 V1 的公开数据、确定性风险指标和来源记录之上，增加历史情景概率预测，以及
DeepSeek 多 Agent 独立分析、交叉反驳、证据审查和裁决。系统只用于研究与投资者教育，
不连接证券账户，不执行交易，不承诺收益。

## 1. V2 输出

对 20、60、250 个交易日分别输出：

- 上涨、震荡、下跌的历史情景比例；
- P10、P50、P90 历史情景收益区间；
- 负收益情景比例；
- 路径中回撤超过 10%、15%、20% 的情景比例；
- 历史滚动窗口数量和可靠性；
- 扩展窗口样本外 Brier Score、等概率和全历史无条件基线比较、最可能方向命中率；
- 多 Agent 的独立观点、风险、交叉反驳、审查问题、分歧和失效条件。

这些结果不是基金销售材料、确定性收益预测或个性化投资建议。

## 合规和产品边界

- [公开募集证券投资基金销售机构监督管理办法](https://www.csrc.gov.cn/csrc/c106256/c1653806/content.shtml)禁止基金销售机构预测基金投资业绩、承诺收益或宣传预期收益率。本项目不是基金销售机构，但不应被用于销售宣传，输出也不得转述为保证性收益。
- [证券投资基金评价业务管理暂行办法](https://www.csrc.gov.cn/csrc/c106256/c1653866/content.shtml)要求基金评价长期、公正、全面，且评价结果不应视为未来预测或投资建议。V2 因此保留样本量、回测基线、模型失败和数据滞后。
- [证券期货投资者适当性管理办法](https://www.csrc.gov.cn/csrc/c101939/c1045348/content.shtml)要求适当性判断结合投资者情况。V2 没有完整个人组合和适当性信息，不输出个性化买卖决定。

V2 的“预测”是历史条件情景的统计研究，不是净值点位、保证收益或销售口径的预期收益率。

## 2. 量化方法和边界

基础概率由 `tradingagents/funds/forecast.py` 计算。程序先按照 `--as-of` 截断净值，使用
当前 20 日趋势、60 日趋势和 20 日波动，在已经完成的历史窗口中选取最多 200 个最相似
情景，再统计其 20、60、250 日后表现。方向判断使用随历史波动和周期调整的震荡带，
收益区间使用经验分位数，回撤概率使用每个相似历史窗口内的实际路径回撤。
相似情景模型必须在扩展窗口样本外同时明显优于等概率和全历史无条件基线；没有通过时，
正式概率自动回退到全历史无条件情景，报告保留回测差距和回退原因。

为了防止虚假精确：

- 少于 60 个完整历史窗口时，该周期不生成任何概率或区间；
- 截止日之后的数据在计算前被删除；
- 样本外检验在每个检验时点只使用当时已经完成的历史窗口；
- 样本外检验在整个历史区间均匀抽取最多 80 个验证时点，控制线上运行时间；
- Brier Score 相比三方向等概率基线的改善不足 0.02 时，可靠性不能标记为“中”；
- 相似情景模型相比全历史无条件概率的 Brier 改善不足 0.01 时，可靠性也不能标记为“中”；
- 报告明确提示滚动窗口彼此重叠，情景数量不等于独立样本数量；
- 当前模型是历史情景分布，不声称发现了可持续的超额收益信号。

## 3. 多 Agent 工作流

完整预测默认调用六个独立分析角色：

1. `data_auditor`：数据日期、缺失、滞后和可预测性；
2. `quantitative`：基础概率、区间、回测及其限制；
3. `holdings_industry`：定期披露持仓、行业集中和披露滞后；
4. `bull`：有证据支持的积极情景；
5. `bear`：有证据支持的消极情景；
6. `tail_risk`：尾部风险和模型失效情景。

第一轮意见并行且相互不可见；数据、持仓和尾部风险角色还看不到基础预测，降低概率锚定。
随后多头和空头进行交叉反驳。`reviewer` 检查证据编号、
重复证据、数字一致性和逻辑跳跃，`judge` 只综合通过审查的证据。

所有事实性声明必须引用证据包中的编号。不存在的编号、直接交易指令和保证性语言会被
确定性代码拒绝。单个 Agent 调用失败不会丢失基础量化结果，报告会标记为“降级”。

### 为什么 V2 不允许 Agent 修改概率

Agent 的历史预测能力还没有经过长期样本外校准。让语言模型直接改变 Python 概率，会把
可复现的历史统计重新变成主观猜测。因此 V2 固定输出：

> 概率调整：未调整。V2 审议层没有经过样本外校准，无权改写 Python 概率。

未来只有在保存足够长的真实预测记录、验证每个 Agent 的增量校准能力后，才能讨论受限
调整，并且仍需保留基础概率、调整幅度和原因。

## 4. 命令行使用

普通 V1 研究报告：

```bash
.venv/bin/python -m tradingagents.funds.cli 110022
```

完整 V2 预测和多 Agent 审查：

```bash
.venv/bin/python -m tradingagents.funds.cli 110022 --predict
```

只验证 Python 基础预测，不调用 DeepSeek：

```bash
.venv/bin/python -m tradingagents.funds.cli 110022 --predict --no-ai
```

历史截止日复现：

```bash
.venv/bin/python -m tradingagents.funds.cli 110022 --predict --no-ai --as-of 2025-12-31
```

真实密钥只能通过环境变量 `DEEPSEEK_API_KEY` 注入。OpenClaw 部署继续使用服务环境中的
`OPENCLAW_DEEPSEEK_API_KEY`，由受控脚本只在子进程中映射。不得把密钥写进仓库。

## 5. OpenClaw 路由

安装后的 Skill 在识别到“预测、走势、未来、涨跌概率、后面会怎样”等意图时调用：

```bash
{baseDir}/scripts/run_fund_advisor.sh 110022 --predict
```

普通基金资料和历史风险请求仍调用单参数模式。预测脚本超时为 600 秒；普通报告保持
300 秒。脚本只接受六位基金代码以及可选的 `--predict`，拒绝其他参数。

## 6. 测试

```bash
.venv/bin/python -m unittest discover -s tests/funds -v
.venv/bin/python -m compileall -q tradingagents/funds tests/funds
bash -n integrations/openclaw/china-fund-advisor/scripts/run_fund_advisor.sh
```

测试覆盖概率和分位数一致性、回撤概率单调性、截止日防泄漏、样本不足拒绝、未知证据
拒绝、危险交易语言拒绝、Agent 调用失败降级，以及 V1 兼容性。

## 7. 当前没有实现

- 基准指数和同类基金的完整相对预测；
- 宏观实时数据或新闻预测；
- ETF 盘中行情；
- 货币基金万份收益和七日年化专用模型；
- 用户组合相关性、组合回撤和持仓成本适配；
- 根据 Agent 历史成绩自动调整权重；
- 自动交易、买卖时点、金额或仓位指令。

内容仅供研究参考，不构成投资建议。
